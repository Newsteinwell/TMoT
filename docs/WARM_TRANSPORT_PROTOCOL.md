# v31 持续残差表示与标准化传输

动机：现有非线性残差分支每阶段重置。v31检验保留已学表示是否改善结果，而不是预先把重置认定为性能差的原因。

固定72条VAL轨迹：七个数据集的Mantis，加两个回归集的summary，共9组表示；高斯统计重放/4MiB真实特征重放 × MSE/任务损失 × 重置/保留。残差惩罚统一0.1，岭参数沿用v12已冻结选择，种子42、类序17，每阶段30epochs，历史重放4096，同批量与更新步数。16路GPU并发，每进程1CPU线程。正式TEST不读取。

设旧标准化为(x-m0)/s0，新标准化为(x-m1)/s1。旧第一层W,b变为W'=W diag(s1/s0)，b'=b+W((m1-m0)/s0)。其余隐层保留；新增类别输出行置零，旧输出坐标顺序保持前缀。该变换只保持残差函数，不保持重新拟合的解析捷径，因此不宣称整个预测器完全不变。

每阶段重新创建优化器，两个版本预算一致；生成新网络后再复制参数，保持torch随机数消耗与控制一致。记录在当前训练样本上的传输前后残差最大绝对差。每条重置控制须精确复现v26对应0.1配置；暖启动/重置的输入、顺序、累计矩、捷径、训练步数与历史样本数须匹配。

这仍是固定底层编码器之上的监督表示适配，不称为端到端微调。若只改善ER而非高斯重放，不能把收益归给统计量框架；如果只有局部收益，同样不满足多数数据集稳健增益的目标。
