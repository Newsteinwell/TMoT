# TMoT 首轮实验验证报告

日期：2026-10-24。研究目标：**面向一般多维时间序列持续学习的算法**。分类、类别增长、域变化与回归是这一目标下的验证路线。本轮已实现动态类别分类与连续目标回归，尚未覆盖全部任务与协议。

## 1. 执行与交付

完成116条完整轨迹：72条类别增量分类、24条机制消融、10条轻量编码回归、10条Mantis编码回归。全部正常完成，逐阶段保存的预测重新计算后与汇总指标一致。5项数学/学习器测试通过，覆盖类别增长、历史损失与梯度等价、仿射传输、矩合并、向量回归。能耗数据的原始时间戳不重叠审计通过。

代码已同步到本仓库与服务器。训练代码版本可在每条结果的`git_commit`字段追溯。基础模型固定为MantisV2 revision `8f6ca35cb54ab14b120618943c6fca5ddf5a76a6`；完整权重SHA256和输入文件哈希见结果与特征元数据。

## 2. 本轮实际实现

统一固定基表示上维护矩统计，持续训练仿射适配器。分类按已观测类别动态增加输出行，从按类统计构造历史平方风险，新输出对旧类别的目标为零；不预知未来标签。回归维护输入二阶矩、输入-目标交叉矩和目标二阶矩，计算历史平方损失；单元测试支持多输出目标，真实先导为单目标。

**这是TMoT v0.1机制原型，不是完整WiMoT的忠实复现。**当前使用首阶段标准化、固定随机ReLU基表示、256→64仿射瓶颈、CE/SupCon及历史平方风险，并从传输矩拟合ridge读出。未包含WiMoT的双stem、首域PCA与完整OSCL/Student-t校准。`ridge`/`ranpac`/`slda`均为文档说明的机制实现，不冒称正式ACIL/RanPAC官方基准复现。

## 3. 类别增长结果

两个类别顺序×两个初始化，共4次/方法/数据集。下表为最终全部已见类别的宏平均准确率，单位%。这是描述性平均，不是统计显著性判断。超参数预先固定，测试指标未用于优化或选择。

| 方法 | HAR | UWave小样本版 | DailySports原始19类 |
|---|---:|---:|---:|
| Fine-tuning | 39.11 | 24.14 | 10.53 |
| Feature replay | 91.00 | 85.62 | 82.68 |
| SLDA-style | 90.44 | 85.62 | 87.70 |
| Cumulative ridge | 89.96 | 84.22 | 85.26 |
| RanPAC-style | 88.80 | 82.97 | 83.40 |
| TMoT v0.1 | 89.70 | 75.08 | 84.98 |
| TMoT，无历史损失 | 84.20 | 72.58 | 77.02 |
| TMoT，首阶段后冻结适配器 | 81.12 | 69.69 | 71.18 |

主指标为跨阶段宏平均准确率，TMoT在三个数据集上分别为95.44%、82.42%、91.19%；该指标也尚未超过各数据集最强已测基线。全部主指标、标准差、遗忘与资源数据见CSV。

**可支持的初步判断：**类别增长接口正常；在相同TMoT结构内，历史约束分别贡献约5.50、2.50、7.96个百分点，持续适配也优于只训练首阶段。但完整原型尚未超过强统计基线。尤其UWave小样本数据上差距较大，不能只用相对普通微调的收益宣称方法优势。

一个需要验证的解释是：TMoT的64维瓶颈与首阶段适配造成表示损失，而统计基线直接使用256维基表示；历史约束改善了受限模型的保持能力，却未抵消信息损失。这是诊断假设，尚未由匹配维度实验确认。

## 4. 回归结果

Appliances Energy共5个连续时间域，390/130/130个训练/验证/测试窗口。输入24个时间步，预测后续6个`Appliances`数值的均值。所有窗口原始时间区间不重叠；按物理目标单位计算RMSE，越低越好。两次初始化，不据此宣称显著性。

| 方法 | 轻量编码最终RMSE | Mantis编码最终RMSE |
|---|---:|---:|
| Fine-tuning | 61.90 | 74.66 |
| Feature replay | 77.48 | 71.21 |
| Cumulative ridge | 90.64 | 84.74 |
| TMoT v0.1 | 71.20 | 70.35 |
| TMoT，无历史损失 | 63.65 | 69.62 |

无训练参照：已见训练目标均值60.69；最近值持久预测65.41；最近6步均值62.56。单位是每10分钟目标间隔的Wh均值，不是未来一小时总能耗。

回归的数学接口和真实数据流程已跑通，但这组实验不支持TMoT优于简单基线。小样本、目标波动、表示尺度、历史权重与读出失配可能影响结果，需要在验证集上分别诊断。该实验是序列到连续目标的先导，不足以支撑通用回归或预测优势。

## 5. 数据与资源边界

- HAR保留官方主体隔离测试集，并从训练主体中划出4个验证主体；实际训练5867、验证1485、测试2947。
- UWave下载包实际为120训练/320测试，训练中24条划为验证。这与官网页面较大版本不一致，已保留ZIP哈希；不是大版本复现，也不宣称主体隔离。
- DailySports采用全部19类，p1–p5训练、p6验证、p7–p8测试；不同于TSCIL处理后的18类版本。
- 骨干特征抽取总计约67秒（不含安装、下载和部分I/O开销）：HAR13.34、UWave0.19、DailySports51.93、Energy1.63秒。数值来自当前机器缓存抽取日志，不适用于其他骨干或完整OSCL。
- 单个梯度训练进程观察到约0.8GB的nvidia-smi显存占用；精确allocated峰值与CPU峰值见各运行JSON。96GB单卡足够本轮验证。
- 本轮代码、原始数据、特征、运行状态只使用少量GB，150GB数据盘尚有充足空间。完整研究的资源需求必须随新增基线重新测量，不能沿用最初150–450小时规划额度作为实测需求。
- Feature replay预算4MiB，但其他方法按实际状态报告，本轮没有声称严格等字节。正式强基线、调参公平性、不同骨干和真实DIL/混合流仍需补充。

## 6. 后续优先级

1. **先做验证集上的匹配维度诊断。**对照64/128/256维，隔离信息瓶颈、首阶段表示偏置与读出因素；保留当前测试结果为探索结果。
2. **补齐忠实WiMoT/OSCL对照。**在通用输入接口与真实DIL上保留其核心损失与读出，判断最小原型简化损失了什么。新增读出也应移植给对应基线做公平比较。
3. **统一风险尺度与读出。**比较梯度训练用的辅助头和最终解析头；检查新类输出约束及回归目标尺度。依据独立验证流固定改动后，再做新的确认实验。
4. **扩展回归证据。**增加不同物理机制、更多样本与多输出目标，保留常数、持久预测和解析回归基线，不以“已跑通”等同于“有效”。
5. 当前先导尚不满足扩大到完整正式实验矩阵的效果门槛。先修正关键机制并形成增量证据，再投入大规模对比。研究目标仍为一般多维时间序列持续学习，不因单个先导结果改写成固定类别分类目标。
